# Повторная проверка 247 (claude-remote-control) — 5 октября 2026

Проверка поверх аудита [AUDIT-2026-10-04.md](AUDIT-2026-10-04.md). Версия 2.44.2.
Git в каталоге по-прежнему не инициализирован.

## 1. Что реально было не так

`pnpm test` показывал «FULL TURBO зелёный», но это был **устаревший кэш turbo**.
При чистом прогоне (`turbo test --force`) падали:

- **agent:** 13 тестов в 5 файлах (`db-index`, `db-schema`, `sessions-db`,
  `api`, `api-contracts`).

Причина — не код, а окружение: нативный модуль `better-sqlite3` собран под
`NODE_MODULE_VERSION 137`, а на машине сейчас Node 26.10.0 (требует 147).
`.nvmrc` проекта фиксирует Node 22. Починено пересборкой:
`pnpm rebuild -r better-sqlite3`. (Бинарник не коммитится; CI пересобирает
под свой Node.) CLI «падение» оказалось ложным — это ожидаемый stderr из
теста `returns null for invalid JSON`.

## 3. Внесённые правки

1. **`apps/web/drizzle.config.ts`** — убран `process.env.DATABASE_URL!`
   (non-null assertion, единственное предупреждение не про console).
   Сделан безопасный дефолт `?? ''` с комментарием: конфиг загружается
   статически инструментами (knip, lint) без `DATABASE_URL`, поэтому бросать
   на этапе загрузки нельзя — ошибку соединения сообщает сам drizzle-kit,
   когда URL реально нужен.
2. **`eslint`-предупреждения `no-console` → 0.** Конфиг трогать нельзя
   (хук config-protection), поэтому точечные file-level `eslint-disable`
   с пояснением в двух файлах, где вывод легитимен и это не продакшн-код:
   `scripts/release/index.ts` (релизная CLI) и
   `tests/duplication/duplication.test.ts` (печать отчёта о дубликатах).
3. **`LICENSE`** — добавлен (MIT, Quivr). README и `package.json` заявляли
   MIT, а файла не было.

## 4. Осталось и требует твоего решения (не трогал намеренно)

1. **`better-auth` (12 advisories, 2 critical)** приходит транзитивно через
   `@neondatabase/auth@0.1.0-beta.21`. Фикс — миграция на
   `@neondatabase/auth@0.5.0-beta` (`createNeonAuth`, другой серверный API):
   ломающая переделка всех точек входа авторизации, проверяется только с
   реальным входом по коду из письма. Нужно твоё решение.
2. **Аутентификация агента** (из §7.1 прошлого аудита) — главный открытый
   риск: Origin-allowlist закрывает браузерные атаки, но любой не-браузерный
   клиент, достучавшийся до порта/туннеля, по-прежнему получает shell.
   Нужен bearer-токен (генерация в `247 init`, проверка в агенте, хранение в
   записи подключения + в хуке). Ломающее изменение.
3. **QR пейринга** строится через внешний `api.qrserver.com` — ссылка с
   токеном уходит третьей стороне. Стоит генерировать QR локально.
4. **`.claude-plugin/marketplace.json`** ссылается на несуществующий
   `./claude-remote-control/packages/plugin-247` (есть только `cli`, `hooks`,
   `shared`). Плагин «247-orchestrator» в репозитории отсутствует. Либо
   убрать запись, либо добавить реальный пакет — это продуктовое решение,
   выдумывать плагин не стал.
5. **Git не инициализирован.** Для «эталона» проект стоит завести под
   контроль версий (есть `.gitignore`, `.husky`, CI-workflows, которые это
   предполагают). Готов сделать `git init` + первый коммит по твоему слову.
6. **`/api/sessions` отдаёт 500 при недоступном tmux** (а не `[]`). Это
   осознанный выбор в коде (tmux недоступен = ошибка сервера). Если дашборд
   должен деградировать мягко до пустого списка — скажи, поправлю с тестом.

## 5. Как перепроверить

```bash
cd claude-remote-control
pnpm rebuild -r better-sqlite3   # только если локальный Node != 22
pnpm lint && pnpm format:check && pnpm typecheck
pnpm exec turbo test --force
pnpm deadcode
pnpm --filter 247-web build
pnpm audit --prod
```
